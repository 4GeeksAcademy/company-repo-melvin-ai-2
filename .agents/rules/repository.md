# Repository Rule

- Read `CONTEXT.md` and all memory-bank files before implementation.
- Preserve the responsibility of every top-level monorepo folder.
- Use company-specific terminology, examples, and acceptance criteria.
- Keep APIs under `services`; do not use UI route handlers as an API substitute.
- Import reusable code from its canonical location instead of copying it.
- Follow the ordered delivery workflow in `AGENTS.md` before any commit.
